## What is good

The fix commit did the hard version of F-3 rather than the easy one. Adding
`spring-boot-starter-jdbc` alone would have traded one silent failure for a louder one at
startup; the author saw that a pooled DataSource with no `spring.datasource.url` is a
liability in a runner that supplies its own credentials, and excluded
`DataSourceAutoConfiguration` deliberately with the reasoning written down at
`MigrationApplication.java:14-17`. Against the 3.3.13 bytecode the reasoning is sound —
the citation is the only thing wrong with it.

Rewriting `FlywayMigrationIT` to boot the real context (`:44-54`) instead of hand-building
a `Flyway` is the right answer to F-4 and the more expensive one. It converts six Flyway
properties from configuration nobody reads into configuration a test fails on. The comment
at `:41-43` says exactly why, which is what stops the next person reverting it for
convenience.

The infra half, unchanged since the first review, is still the strongest part:
`03-grants.sql:59-63` does not merely omit the grant to `app_user`, it asserts the
omission, so provisioning fails loudly if anyone adds it later. And `smoke.sh:39-40`
remains the only gate in the whole run that caught F-3 — the author wrote the check that
failed their own code and left it in.
