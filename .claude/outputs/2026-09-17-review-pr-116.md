## Checks that came back clean

Nginx location precedence is correct — `location = /env.js` beats `location /`, and the
nested `location = /index.html` is reached on the `try_files` internal redirect, so both
no-cache rules bite (`default.conf:42-44,56-64`). `exec` is used in both entrypoints
(`backend-entrypoint.sh:33`, `frontend-entrypoint.sh:21`), so SIGTERM reaches the JVM and
nginx — `server.shutdown: graceful` is not a lie. All four base tags match the spec.
`compose.yml:131-133,159-161` supplies the DB env and `application-local.yml:12-14`
overrides the defaultless placeholders, so the local stack is not broken. No `ddl-auto`
anywhere in `code/` or `infra/`. Nothing under `legacy/` touched.

## What is good

The role-selector entrypoint is the part to copy elsewhere: defaults to `app`, rejects an
invalid role with a named error and a non-zero exit rather than a silent fallback, checks
the jar exists before launching, and `exec`s — four things that are each one line and each
individually skipped by most implementations. The frontend runtime-config split is right in
a way that is easy to get wrong: `public/env.js` ships a valid placeholder so a dev build
and a container with a failed entrypoint both degrade to a working page, `index.html` loads
it as a classic script ahead of the deferred module bundle, and `client.js` keeps the
`import.meta.env` path as a genuine fallback rather than ripping it out. `USER root` →
chown → `USER 101` in the frontend Dockerfile is the correct, boring way to make a writable
webroot for an unprivileged runtime. And the comments earn their space — the
`04-runtime-containers.md` references and the note on why the worker is not
`web-application-type: none` mean the next person will not undo these decisions by accident.
