## Are the new tests real?
`TenantBindingPoolLeakIT` fails against the old code and cannot pass vacuously: it asserts the
binding **is** present inside transaction 1 (`:149-151`) and empty on the same pooled session
afterwards (`:158-160`), then that RLS returns zero rows unbound (`:162-164`). A proxy that did
nothing at all would fail the first assertion.

`TenantBindingDataSourceProxyTest` is eleven behavioural tests, including the D-57 throw and a
`mockStatic` proof that binding routes through `TenantDatabaseInterceptor`.

`TenantBindingIT` gaining `@Transactional` did not weaken it — it still asserts the bound tenant
and `rowCount = 1`, and CI ordering leaves three tenant rows in the table, so 1 proves RLS
filtered rather than that the table was nearly empty.

## In plain English
- F-10, F-11, F-6: fixed, and fixed at the root rather than around the edges.
- F-20: the code now refuses to run a query when someone forgot the transaction, instead of quietly returning nothing. That is the better failure, but it is a new platform-wide rule no document states — the first person to write a plain database read in a controller gets a 500 and no clue why.
- F-19: the proxy can be stepped around by asking the connection for the real one underneath. Nobody does that today; the day someone uses a PostgreSQL-specific API, their queries come back empty rather than failing.
- F-21: the leak test works because the pool holds exactly one connection, and nothing checks that it still does.
- F-22: the spec's verification table quotes a test count the last two commits made out of date.
- Carried findings: as tabled in round 2, not re-argued. F-12 and F-13 belong at the front of W-10.

## What is good
The fix chose the correct mechanism. Binding lazily at the first statement is the one place the
transaction is guaranteed to have begun, and routing through `TenantDatabaseInterceptor` leaves
exactly one piece of `set_config` SQL in the production path with the D-57 guard in front of it.
The class comment at `TenantBindingDataSourceProxy.java:13-33` explains why the old approach
failed, with the finding number — the kind of comment that stops a defect coming back. The flag
is reset on every boundary including `setAutoCommit(true)`, and `rollback(Savepoint)` falls out
correctly. `TenantBindingPoolLeakIT` is a genuine regression test. And the honest comment at
`TenantBindingPoolLeakIT.java:53-63` about why the test context is configured as it is will save
the next person an hour.
