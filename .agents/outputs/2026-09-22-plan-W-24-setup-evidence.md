- **UserInvitation:** No expiry_date column; invitation valid forever (potential security concern)

## Gaps & uncertainties

1. **UserInvitation expiry:** No expiry_date column means invitations remain valid forever. No documented expiry check anywhere. Target state may want to add expiry handling to match EmployeeInvitation (which expires after 7 days).

2. **Keycloak password setup:** Where is the employee's password set in Keycloak? Employee invitations don't show password generation/reset flow. Likely happens separately via employee portal password-reset flow, but not traced here.

3. **Resend logic:** Both invitation types rely on delete + recreate to resend. No dedicated resend endpoint or service method. Target state may want a single "resend" operation that regenerates token and resends email without hard delete.

4. **Module-aware checklist:** The build order (`09-build-order.md:211`) says "a HRMS-only tenant never sees a provident fund step." Current design has fixed 9 steps with no module awareness. Target state must implement dynamic step availability based on subscription modules, not hard-coded steps.
