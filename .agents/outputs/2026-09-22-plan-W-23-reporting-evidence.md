## 1. Export implementations today

### Payroll — Excel Pay Run Reports
**Controller:** `controller/payruns/PayRunReportController` (all-pay-runs and single pay-run exports)

- `/api/payruns/report/excel` — multi-pay-run consolidated report with 3 sheets (summary, employee details, pay-run-wise)
- `/api/payruns/{payrunId}/report/excel` — single pay-run report with summary + employee details

Both generated by `ExcelReportService.generateAllPayRunsReport()` and `ExcelReportService.generateSinglePayRunReport()`, using Apache POI `XSSFWorkbook`. Built in-memory via `ByteArrayOutputStream` at line 186-192, then returned as `byte[]` with `CONTENT_DISPOSITION: attachment`.

**Library:** Apache POI (org.apache.poi:poi-ooxml), lines 10-11 of ExcelReportService.java.

## 2. Streaming vs. In-Memory

All exports are **in-memory**, no streaming found.

- Excel: `ByteArrayOutputStream` → `workbook.write(outputStream)` → `outputStream.toByteArray()` — entire file buffered before return
  - `ExcelReportService:186-192`
  - `CtcStructureController:333-344`

- CSV: `StringWriter` → `CSVPrinter` → `writer.toString().getBytes()` — entire CSV buffered before return
  - `EmployeePayRunServiceImpl:1735-1743`

For a 5000-employee export, a single in-memory CSV or Excel file could reach 5–20 MB depending on columns and formatting. No pagination, streaming, or chunking detected.

## 3. Report Definition / Configuration Entity

**Not found in either HRMS or Payroll.**

The FEATURE_MAP (line 154) mentions `entity/Report.java` in HRMS dashboards context, but searching `legacy/HRMS_Backend/src` finds no Report entity file. No controller, service, or repository exists to define user-configurable reports.

All exports are hardcoded in services (e.g., pay run summaries always include 9 fixed columns). No metadata table, no step-through wizard, no scheduled report builder.

## 4. Scheduled or Emailed Reports

**None found.**

Payroll backend has `@Scheduled` tasks:
- `scheduler/POIReminderScheduler.java` — proof-of-investment reminders (not reports)
- `scheduler/ITDeclarationAutoLockScheduler.java` — auto-lock tax declarations (not reports)

HRMS has:
- `scheduler/NotificationSchedular.java` — timesheet reminders
- `scheduler/ReminderScheduler.java` — generic reminders

**No `@Scheduled` method generates or emails a report.** No cron expression generating consolidated pay run or employee reports on a schedule.

## 5. Endpoint Count & Code Sharing

| Endpoint | Format | Controller | Service | Shared |
|---|---|---|---|---|
| `/payruns/report/excel` | Excel | PayRunReportController:29 | ExcelReportService | POI |
| `/payruns/{payrunId}/report/excel` | Excel | PayRunReportController:77 | ExcelReportService | POI |
| `/payruns/{payrunId}/download` | CSV | EmployeePayRunController:159 | EmployeePayRunService | Commons CSV |
| `/employee/revisions/export` | Excel | CtcStructureController:328 | CtcStructureService | POI |
| `/documents/{documentId}/download` | URL | EmployeeProofOfInvestmentController:498 | CloudinaryService | Cloudinary |
| `/documents/{documentId}/download` | URL | POIController:219 | CloudinaryService | Cloudinary |
| `/test/generate-test-report` | Excel | ExcelTestController:33 | ExcelReportService | POI |

**Distinct endpoints:** ~5 export, ~2 document fetch (really URL return, not export), 1 test.

**Code sharing:** 
- Both Excel endpoints (`/payruns/report/excel` and `/payruns/{payrunId}/report/excel`) call `ExcelReportService` — same CellStyle, header format, currency formatting.
- Salary revisions also use POI but via separate `CtcStructureService.exportRevisedCtcs()`.
- CSV has dedicated path in `EmployeePayRunService.generateCsvData()`.
- Document downloads are read-only URLs, not generated.

**No shared "export" base class or template.** Each service generates its own formatting logic.

## Flag: "report" table ambiguity

**Target state mapping issue found:**

`docs/target-state/02-data-model.md:130` maps `core.report_definition` to "HRMS `report`". The FEATURE_MAP entry 10 (line 154) mentions `entity/Report.java`. However:
- No `Report.java` file exists in `legacy/HRMS_Backend/src`
- FEATURE_MAP line 87 also mentions `entity/report` as part of the `leaveAndAttendance` leave data consumed by Payroll (`EmployeeMonthlyLop` query)
- The employee "reporting hierarchy" concept (who reports to whom for leave approvals) uses a `report` field in the `work` table (not a separate entity)

**Likely:** `report_definition` should map to a non-existent or misnamed reporting entity in HRMS, or the field exists but is not yet surfaced as an entity. Confirm before finalizing the data model mapping.
